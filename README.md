# wzsc-collector

把网页文章（微信公众号 / 知乎 / 微博 / X）采集为 Markdown，存进个人收藏仓库。

用法就是给它一个网址：

```bash
node src/cli.js https://mp.weixin.qq.com/s/xxxx
```

它会用你本机浏览器的登录态打开文章，提取**标题、原文链接、作者、时间、正文、图片、视频地址和评论**，
把图片下载到仓库里，然后写出一篇 `编号.标题.md`。**不会自动提交**，你检查完自己 commit。

## 支持的站点

| 站点 | 标题/作者/时间 | 正文 | 图片 | 评论 | 需要登录 |
|---|---|---|---|---|---|
| 微信公众号 | ✔ | ✔ | ✔ | ⚠️ 走文章内联的评论接口（`mp/appmsg_comment`），能取到就带留言+作者回复 | 否 |
| 知乎 | ✔ | ✔ | ✔ | ✔（可筛"作者回复/作者赞过"） | 评论需要 |
| 新浪微博 | ✔ | ✔ | ✔ | ✔ | 需要 |
| X (Twitter) | ✔ | ✔ | ✔ | 作者自己的 thread 推文 | 需要 |
| 其他网页 | 视站点 | 通用正文提取 | ✔ | — | 否 |

单个站点抓不到时会回退到「通用网页」策略；要加新站点，见下方「扩展站点适配器」。

## 安装

需要 Node.js 18 以上（`node -v` 检查）。本项目用 `playwright-core` + **系统自带 Edge/Chrome**，
不会额外下载几百 MB 的浏览器内核。

```bash
npm install
```

## 首次使用：登录

采集知乎评论、微博、X 需要登录态。运行一次：

```bash
npm run login
```

会打开一个浏览器窗口，在里面正常登录知乎 / 微博 / X，登录信息保存在 `.browser-profile/` 目录，
以后采集直接复用（这个窗口不会自动关闭，登录完按 `Ctrl+C` 结束即可）。

## 配置

复制 `config.example.json` 为 `config.json`，按需修改：

| 字段 | 说明 | 默认 |
|---|---|---|
| `repoPath` | 收藏仓库路径（md 和图片都写到这里） | 必填 |
| `assetsDirName` | 图片目录名 | `assets` |
| `images` | `download` 下载图片到仓库（存档自包含、显示稳定）/ `keep-remote` 只保留图片外链（仓库最小，但依赖原站） | `download` |
| `includeComments` | 是否采集评论 | `true` |
| `commentFilter` | `author` 只留与作者有互动的 / `all` 全留 / `none` 不留 | `author` |
| `video` | `poster` 只存封面图+视频地址 / `none` 不存 | `poster` |
| `browserChannel` | 用哪个浏览器：`msedge` / `chrome` / `null`（用自带 Chromium，需另装） | `msedge` |
| `userDataDir` | 浏览器登录态保存目录 | `.browser-profile` |
| `headless` | 是否后台运行（首次登录请用 false） | `false` |
| `delaySeconds` | 批量采集时每篇之间的随机等待区间（秒） | `[5, 12]` |
| `maxComments` | 每篇最多保留多少条评论 | `50` |
| `filenameTemplate` | 文件名模板（`{num}` 编号、`{title}` 标题） | `{num}.{title}` |

## 用法

### 方式一：双击运行（推荐，不用打命令）

在项目目录里直接双击这些文件：

| 文件 | 作用 |
|---|---|
| `开始使用.cmd` | 打开菜单，1/2/3/4 选着做 |
| `1-首次登录.cmd` | 首次登录知乎 / 微博 / X（只需一次） |
| `2-采集一篇文章.cmd` | 粘贴链接就能采一篇 |
| `3-补录公众号留言.cmd` | 先在微信复制留言，再输入文章编号 |
| `4-打开收藏仓库文件夹.cmd` | 打开仓库，查看刚采到的文章 |
| `6-还原图片外链.cmd` | 把早期下载到 `assets/` 的图片还原成原始外链，并删掉图片目录 |

（可以把这些 `.cmd` 右键 → 发送到 → 桌面快捷方式，以后从桌面双击即可。）

### 方式二：命令行

```bash
# 采一篇
node src/cli.js https://www.zhihu.com/question/123/answer/456

# 一次采多篇
node src/cli.js <链接1> <链接2> <链接3>

# 从文件读链接（一行一个）
node src/cli.js --file urls.txt

# 只看结果不写文件
node src/cli.js --dry-run <链接>

# 后台运行（不用看浏览器界面；登录态已保存时可用）
node src/cli.js --headless <链接>
```

### 方式三：浏览器扩展（推荐，直接用你已登录的浏览器）

优点：**不需要单独登录**——扩展跑在你日常浏览器里，用的就是你已经登录的账号，
所以知乎评论、微博、X 的回复都能直接抓到。

**安装（一次性）**

1. 双击 **`启动收藏服务.cmd`**（本机服务，保持窗口开着）
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`
3. 打开右上角**开发者模式**
4. 点**加载已解压的扩展程序** → 选择本项目文件夹（`wzsc-collector`）
5. 工具栏上会出现扩展图标

**使用**

1. 正常浏览文章（确保浏览器里已登录对应站点）
2. 点扩展图标 → **保存这篇文章**
3. 收藏仓库里就会出现 `编号.标题.md`（图片一起下载），服务窗口会打印日志

保存过程中页面会**自动滚动、展开"阅读全文"、点开评论区并加载更多评论**，这是正常现象。
服务窗口关掉后就不能保存了（图标里会提示"本机服务未启动"）。

### 把老的本地图片还原成原始外链

早期版本会把图片下载到 `assets/<编号>/` 里。改成"只留外链"（`images: keep-remote`）以后，
老文章里已经下载的图片可以用这一条命令换回原来的网络地址：

```bash
node src/restore-images.js          # 只检查，不改任何文件
node src/restore-images.js --apply  # 确认无误后正式清理
```

双击 `6-还原图片外链.cmd` 会先检查一遍，把它发现的结果列给你看，问过你之后才真正清理。

它**不是**按顺序猜的：会重新打开原文页面，把页面上能找到的图片逐张下载下来，
和本地文件做内容指纹（sha256）比对，两边内容完全一致才替换，并删掉没人引用的
`assets/` 子目录。只要有一张对不上，那个文章文件就原样保留，不会出现破图。

有几个注意点：

- 评论区头像属于第三方账号，往往**只有登录状态**才能看到，所以清理前建议先跑一次
  `1-首次登录.cmd`（登录知乎 / X）。
- 评论列表有时一次只给一部分，程序会把每次的比对结果累积在 `debug/restore-image-cache.json`，
  多跑几次能补齐更多。
- 想把过程看清楚，加 `--dump` 会把页面快照存到 `debug/`。

### 微信公众号的评论：粘贴补录

公众号文章在网页端不渲染评论区（微信客户端里才有），而评论接口有风控、需要微信登录态，
所以评论用「复制 + 粘贴」补录——保留你平时的习惯，只把排版自动化：

1. 在微信里打开文章（发到聊天框再点开，就是微信内置浏览器），复制留言区文字
2. 运行：

```bash
node src/paste-comments.js 478            # 478 是文章编号；不带文件参数时读剪贴板
node src/paste-comments.js 478 comments.txt
node src/paste-comments.js 478 --dry-run  # 只看解析结果，不写入
```

复制出来的文字大致是「昵称 → 赞184 → 留言正文」这样一组一组排列，工具会自动识别，
遇到作者本人的回复（昵称后带「作者」或单独一行 `(作者)`）会标记成作者。
解析结果会替换该文章里已有的 `**精选留言**` 区块（没有就追加）。

输入/输出示例见 `examples/paste-comments-input.txt` 和 `examples/paste-comments-output.md`。

## 输出示例

```markdown
## [文章标题](https://原文链接)

作者 · 2026-01-01 12:00

正文段落……

![](assets/478/img-1.jpg)

**精选留言**

- ![](assets/478/avatar-1.jpg)
  某读者
  赞184
  这条评论……
```

图片放在 `<仓库>/assets/<编号>/` 下，md 里用相对路径引用。

这个格式和基于 Gmeek 的静态博客管线兼容：把收藏仓库接到博客构建流程后，
图片会自动带上、留言会渲染成卡片，收藏的增删也会自动同步。

## 隐私与安全

- **不会上传任何东西**：工具只在本机读写文件，唯一的外部访问就是浏览器打开目标网页本身
- 下面这些内容已被 `.gitignore` 排除，**不会**进入你的 Git 仓库：
  - `.browser-profile/` —— 浏览器登录态（包含 cookie，最重要的一项）
  - `config.json` —— 你的本地路径等配置
  - `debug/` —— 抓取出问题时保存的页面快照
  - `node_modules/`
- 采集到的文章与图片都写进你指定的收藏仓库，不会发往任何服务器
- 建议：把**工具本体**（本目录）和**收藏仓库**（`repoPath`）分开管理，前者可以开源，后者建议设为私有

## 已知限制

- **微信公众号的评论**：网页版页面不渲染评论区，本工具改为直接调用文章里内联的评论接口
  （`mp/appmsg_comment`，参数从页面里提取）。若该接口要求微信登录态而取不到，会打印原因并跳过评论，
  正文与图片不受影响。
- X / 微博 的页面结构经常变，选择器可能需要跟着更新（改 `src/extractors.js` 即可）
- 频控：请保持 `delaySeconds` 的间隔，别高频批量抓取，避免账号被风控
- 本工具只用于**个人存档**；请遵守目标站点的服务条款，不要公开分发采集到的内容

## 扩展站点适配器

1. 在 `src/extractors.js` 里加两个纯函数（在页面里执行，不能引用外部变量）：
   - `extractXxx()` → `{ site, title, author, date, canonical, contentHtml, videos }`
   - `extractXxxComments()` → `[{ avatar, nick, likes, text, author, replies }]`（可选）
2. 在 `src/sites.js` 的 `SITES` 数组里加一条：`{ id, label, test(host), referer, extract, extractComments, prepare }`
3. `prepare(page, config)` 用来滚动页面、点开"展开全文/更多评论"等

`extract` / `extractComments` 会被序列化后在浏览器里执行，所以必须是自包含函数。
